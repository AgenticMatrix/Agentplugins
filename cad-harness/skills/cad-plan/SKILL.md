# cad-plan

产出 `plan.md`（11 章）到 workspace 根目录，作为 BOM / 建模 / 装配 / 校验的取数来源。

## 路由

| 目标 | 走这里 |
|---|---|
| 多零件装配体、带机构/运动对象 | **本 skill** |
| 单零件（支架、法兰、摇臂…） | `$cad-component-generation`，不产 `plan.md` |
| STEP 导入 / 测量 / 对齐 / 导出 | `$cad` |

## 工作流

### 1. 判断输入形态

用户给的东西决定起手动作。**先判形态，再动笔。**

| 输入形态 | 判据 | 起手动作 |
|---|---|---|
| **纯需求描述** | 只有文字需求 / 图片 / 指标，无既有文档 | 直接走步骤 2–4 |
| **已有规划或规格文档** | 用户贴了一份「设计方案」「技术规格」「零件清单」 | **先体检，再改写**（见下）——不要顺着原文档的颗粒度往下写 |
| **已有 CAD / BOM** | 有 STEP 文件或 `bom.md` | 先 `inspect refs --facts` + `inspect bom` 反推现状，再补 `plan.md` 缺的章 |

#### 已有文档 → 体检协议

既有文档**大概率是拆浅的**（散文式、章节不对齐、集合名词当零件）。直接改写会继承它的缺陷。按顺序做：

1. **章节映射**：逐条列出「原文档第 X 节 → 本模板第 Y 章 / 无对应 / 应删（制造工艺）」。缺的章标「缺」。
2. **逐行 toy 自查**：对原零件表逐行跑第 4 章危险信号表，命中的写行号 + 拆法。
3. **规模对照表**：

   | 项 | 原文档 | 本次规划 |
   |---|---|---|
   | 叶子零件类型数 | 36 | 112 |
   | 有骨架 ID 的定位基准 | 0 | 112 |
   | 可执行的装配步骤 | 0（全是工艺） | 68 |

4. 然后按步骤 2–4 **重写**，不是编辑。原文档只作为需求与指标来源。

> ⚠️ **原文档的零件数不是目标值**，是需要被超过的基线。原文档 36 类不代表本次也该 36 类。

### 2. 先写第 0 章（范围预算），再写其余 10 章

LOD 决定后 10 章的详细程度。先定 LOD：

| LOD | 叶子零件**类型数** | 用途 | 公差表 | 骨架 |
|---|---|---|---|---|
| L1 外观级 | ≥ 20，≤ 50 | 渲染、比例演示 | 免 | 简化 |
| L2 功能级 | ≥ 50，≤ 300 | 装配演示、运动仿真 | 关键配合 ≤ 15 项 | 完整 |
| L3 工程级 | ≥ 150，无上限 | 结构分析、出图 | 全接口 | 完整 + 子骨架 |

- 统计口径 = 类型数（不重复种类），非物理件数。
- **下限是硬性的**：低于下限 → 存在 toy 架构，按第 4 章「toy 架构自查表」逐行再拆一层。
- 超上限 → 归并为实例或降级占位，在第 0 章写明取舍。
- 「1 源 + N 实例」用于控制工作量；**少拆不是控制手段**。

**下限豁免**：对象真实零件数就是不多（简单夹具、纯壳体件）时，在第 0 章写「下限豁免声明」——**必须逐条回应 6 个危险信号**，每条说明本对象为何不命中。少写任何一条即无效。**绝不允许为凑下限而虚构不存在的零件**：那比拆浅更糟，会污染 BOM 且阶段 2 建不出来。

### 3. 按 `references/planning-template.md` 写 11 章

第 0–9 章必填，第 10 章可选。

对象含 ≥3 个功能子系统，或预期 ≥50 类 → **必须先读 `references/large-assembly-example.md`** 对齐颗粒度。

### 4. 跑 plan-lint，再跑自检清单

```bash
$CAD_PYTHON $CAD_SKILL_DIR/cad-plan/scripts/plan-lint plan.md
```

纯标准库脚本，机械校验章节完备性 / 骨架 ID 悬空与未引用 / 定位基准是否填 ID / 类型数与预算区间 / 自查结论行是否逐行扫描 / 数量模糊词 / 来源标记 / 装配顺序 / 工艺混入 / 公差阈值。

**exit code 非 0 → 不输出 `plan.md`**，回去改到 0 error。脚本管机械项，语义项（拆得够不够深、参数自不自洽）仍由下方清单和你自己负责。

## 章节取数关系

| 章 | 下游消费方 | 取什么 |
|---|---|---|
| 0 范围与规模预算 | 全流程 | LOD、类型数区间、停止点 |
| 1 总体构型与技术指标 | 阶段 0 | 功能定义、包络尺寸 |
| 2 骨架与基准体系 | 阶段 3 | **装配定位的唯一来源**：CSYS / 基准面 / 站位 / 阵列轴 ID |
| 3 全局参数驱动表 | 阶段 2 | `gen_step(params)` 的共享参数 |
| 4 零件明细表 | 阶段 1 | **`bom.md` 的唯一来源** |
| 5 系统布线 / 驱动路径 | 阶段 1 | 谁与谁相接 → 接口契约配对 |
| 6 自由度与耦合 | 阶段 3 | joint 类型 + 轴线 ID；记录运动能力需求 |
| 7 限位与过载保护 | 阶段 2 | 挡块 / 卡簧槽 / 缓冲等要建的几何特征 |
| 8 CAD 装配顺序 | 阶段 3 | 逐步装配 + 每步 inspect 命令 |
| 9 关键配合公差 | 阶段 3/4 | inspect 验收阈值 |
| 10 类比说明（可选） | — | 暴露驱动链遗漏 |

写每章前自问：**阶段 1/2/3/4 从这一章取哪个值？** 取不出值的内容不写。

## 与 `bom.md` 的关系（单一真值）

**零件表的唯一真值在 `plan.md` 第 4 章。** 阶段 1 的 `bom.md` 只做两件事：

1. 声明「零件表见 `plan.md` 第 4 章」，不复制粘贴一份。
2. 承载 plan.md 没有的运行期信息：粒度声明、外部件版本锁（catalog 路径 + 校验和）、文件名 ↔ 零件名映射。

零件有增删改 → 改 `plan.md` 第 4 章 + 登记修订记录，然后 `inspect bom --check-bom` 校验文件系统与之一致。**不要在 `bom.md` 里改零件表。**

## 修订

阶段 1–4 发现规划有问题要回流改 `plan.md`。**改完必须在 `plan.md` 顶部的「修订记录」表登记**，否则下游无法判断哪些 `.step.py` 要重建。

传播规则：

| 改了什么 | 必须做什么 |
|---|---|
| 第 2 章骨架 ID 或坐标 | 按该 ID 的「被引用零件」列逐个重跑 `gen_step` + 重跑该步 `inspect align` |
| 第 3 章参数 | 按该参数的「被引用于」列逐个重建零件 |
| 第 4 章零件增删改 | 同步文件系统 + 重跑 `inspect bom --check-bom`；类型数变了要回第 0 章核对预算区间 |
| 只改第 1 / 5 / 7 / 10 章 | 不触发重建，仅登记 |

修订记录表：`版本 | 日期 | 改动章节 | 改动内容 | 触发重建`。

## 自检清单（不过则不交付）

先跑 plan-lint 清掉机械项，再逐条过下面的语义项。

**A. 范围一致性**
- [ ] 第 0 章有：LOD 等级、类型数下限与上限、子系统拆解深度表、三个停止点。
- [ ] 第 4 章实际类型数落在区间内；低于下限时有完整的 6 条豁免声明。
- [ ] 第 9 章公差项数符合该 LOD 档位。

**A2. 拆解深度**
- [ ] 逐行跑过第 4 章「toy 架构自查表」，结论行的「扫描 N 行」等于零件表实际行数，命中项列了行号。
- [ ] 无集合名词单行（发动机 / 泵 / 电机 / 阀组 / 控制器 / 线束…独占一行而无下级）。
- [ ] 无「1 套」「若干」「~N 个」这类无确定几何的数量。
- [ ] 每个可动机构列全杆件 + 铰链 + 作动器 + 锁定件。
- [ ] 带「组 / 总成 / 系统 / 装置」后缀的条目都有下级零件。
- [ ] 零件表里每一行都对应目标对象上真实存在的件，无为凑数虚构的条目。

**B. 骨架可用性**
- [ ] 第 2 章有全局 CSYS（原点物理位置 + 三轴指向含义）。
- [ ] 每个主要子系统有基准面/轴，且有唯一 ID（`CSYS_*` / `PLN_*` / `AX_*` / `STA_*`）。
- [ ] 第 2 章骨架表有「被引用零件」列，且与第 4 章「定位基准」列互相对得上。
- [ ] 第 4 章「定位基准」列填的是第 2 章 ID，不是自然语言方位。

**C. 参数可驱动性**
- [ ] 第 3 章每个参数有：`snake_case` 名、值、单位、来源标记、被引用零件。
- [ ] 凡在 ≥2 个零件出现的尺寸，第 3 章必须有条目。
- [ ] 派生参数写公式，不只写结果。

**D. 零件表完整性**
- [ ] 每行有：LOD、材料/规格、颜色、数量、实例性、对称性、来源、定位基准 ID。
- [ ] 颜色列取自 `$CAD_SKILL_DIR/references/materials.md` 速查表；`import` 件写「库内」。
- [ ] 同参数重复件标「1 源 + N 实例」。
- [ ] 标准件已查 `$STEP_PARTS_DIR/catalog.json`，命中的写了相对路径。

**E. 自由度可实现性**
- [ ] 每个自由度有：joint 类型（revolute / prismatic / spherical / cylindrical / fixed）、轴线 ID、范围、驱动源。
- [ ] 多杆/连杆机构显式列全杆件与铰链，不简化成单铰链。
- [ ] 第 6 章末尾记录了运动能力需求，但没有替用户决定走 `$urdf` / `$cad-animate`。

**F. 装配顺序可执行性**
- [ ] 每步产出几何或位姿变化。
- [ ] 每步写清：加入零件 + 对齐到哪个基准/已装零件的面或轴 + offset + 校验命令 + 阈值。
- [ ] 第 1 步是基准件，直接约束到全局 CSYS。
- [ ] 后续步骤只引用已装入的零件或骨架，无前向引用。

**G. 数据诚实性**
- [ ] 每个数值有来源标记：`[用户给定]` / `[标准件推导]` / `[典型值]` / `[⚠️假设-待确认]`。
- [ ] 复刻真实产品时未公开数据一律标 `[⚠️假设-待确认]`，第 0 章加免责声明。
- [ ] 第 9 章公差对齐 harness 阈值：面贴面 ≤ 0.01 mm、轴共线 ≤ 0.01 mm、孔位 ≤ 0.05 mm。严于此者须写明理由。

## 禁止

- 跳过 `plan.md` 直接建几何。
- plan-lint 有 error 却仍然交付 `plan.md`。
- 写散文——关键参数必须落表。
- 把集合名词当零件（「发动机」「涡轮泵组」「线束 1 套」独占一行而无下级）。
- 为控制规模而少拆——用「1 源 + N 实例」控制工作量。
- **为凑够类型数下限而虚构目标对象上不存在的零件。** 真拆不够就写豁免声明。
- 顺着用户给的既有文档的颗粒度往下写——先体检，再重写。
- 在 `bom.md` 里另立一份零件表。
- 在第 6 章替用户决定走运动路线——只记录能力需求。
- 把制造工艺（焊接、热处理、无损检测、试压、点火试验）写进第 8 章。
- 编造真实产品的内部尺寸/公差却不标 `[⚠️假设-待确认]`。
- 阶段 3 出现未引用第 2 章骨架 ID 的绝对坐标 —— 视为规划缺失，回本 skill 补骨架。
- 启动常驻 viewer / server 进程。
- 用 `Read` 读图片快照（几何校验用 `inspect`，视觉质检用 `mcp__cad-vlm-judge__evaluate_cad_step`）。

## 工具

| 命令 | 用途 |
|---|---|
| `$CAD_PYTHON $CAD_SKILL_DIR/cad-plan/scripts/plan-lint plan.md` | 机械校验，交付前必跑 |
| `… plan-lint plan.md --format json` | 机读输出，便于逐条修 |

## 最终响应

`plan.md` 路径、输入形态与体检结论（若有既有文档）、LOD 与类型数（下限/上限/实际）、11 章摘要、toy 架构自查结论（扫描 N / 命中行号 / 拆后类型数）、plan-lint 输出（error/warning 计数）、标准件清单、全部 `[⚠️假设-待确认]` 参数汇总。
